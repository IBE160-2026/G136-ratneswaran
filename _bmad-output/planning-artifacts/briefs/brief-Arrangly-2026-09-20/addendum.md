# Addendum: Arrangly product brief

Depth carried over from the Norwegian brief (2026-09-16) and the discovery conversation. For downstream use in the PRD, UX and architecture.

## Origin story
Founder planned a wedding party single-handedly: guest list, chasing RSVPs, venue, catering, DJ, photographer, decorations, decorating groups, bar menus, table decor, seating charts, and delegating roles (sermon, toastmaster, speeches). Hardest parts: everything has to happen in order, some things far ahead, and communication with contributors. Biggest failure: not delegating hands-on work (stayed a doer, not a manager) and not being able to track role-holders' progress.

## Role examples
- Food lead: decide menu, map allergies, calculate quantities, buy, prepare, coordinate serving.
- Other roles: finance, toastmaster, technical, security, decorating.
- Role-holder who is also a guest: a birthday guest can get access to the guest list without seeing the surprise planning.

## Ripple examples (AI decision support)
- Adding a DJ: find and choose vendor, request quote, sign agreement, clarify music wishes, check sound and light needs, plan rigging, add soundcheck, place the DJ in the run of show.
- Guest count change: affects food, seating, staffing, budget.
- Gap detection examples: no time for table setting between welcome drink and dinner; DJ needs soundcheck but none is planned; quiz needs a projector but nobody owns technical equipment; venue must be cleared at 01:00 but the program ends at 01:00 with no time to strike.
- Delay example: dinner runs 25 minutes long, which affects speeches, quiz, technical changeover and DJ start; the organizer decides what to move, shorten or keep.

## Constraints and context
- Course exam project; working web platform built with Claude; BMAD method required; 70 days; difficulty is graded against time available; instructor gives feedback on custom proposals.
- Web application only (guest side must work on phone browsers).
- Tech stack open; decided in architecture phase.
