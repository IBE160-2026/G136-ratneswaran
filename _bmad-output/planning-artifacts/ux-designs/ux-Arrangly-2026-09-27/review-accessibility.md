# Accessibility Review — Arrangly

Reviewed: DESIGN.md and EXPERIENCE.md (draft, 2026-09-28) against WCAG 2.2 AA. All contrast ratios below were recomputed with the WCAG relative-luminance formula; they are not taken from the spine's own claims.

## Overall verdict

**Not ready. Fix before build.** The intent is strong: status is never colour-only, there is undo instead of confirm dialogs, reduced motion is respected, `lang` is set, and focus moves to the title on full pages. But one component spec fails contrast outright in dark mode (Decide button), the notification badge fails text contrast in both modes, and the input, switch and focus-ring specs are silent or inherit near-invisible borders. The 5s undo toast is not reachable by screen-reader or keyboard users. The Timeline and the reflow target (375px, not 320px) are also under-specified. Most fixes are one line in a spine.

Counts: **1 critical · 9 high · 11 medium · 5 low**

## Findings

- **[critical]** The Decide button is white text on `status-decision-dark` `#D08CF2` in dark mode, which is **2.41:1**. `decide-button.foreground` is hard-coded `#FFFFFF`, so builders will ship this on the loudest control on the Dashboard. (DESIGN.md › components.decide-button; SC 1.4.3). *Fix:* add `decide-foreground: '#FFFFFF'` / `decide-foreground-dark: '#000000'` (black on #D08CF2 = 8.72:1) and reference the token in the component. Audit every other hard-coded `#FFFFFF` foreground the same way.
- **[high]** The notification badge is white on `#FF3B30`, which is **3.55:1**, and white on `#FF453A` in dark mode, which is **3.41:1**. The badge carries a number (small text), so 4.5:1 applies. (DESIGN.md › colors.badge, components.notification-badge; SC 1.4.3). *Fix:* use `badge: '#D70015'` (5.38:1 with white). For dark mode, use `#D70015` too or pick a red that reaches ≥4.5 with white. Correct the "measured" contrast paragraph to list the badge.
- **[high]** Input, checkbox and switch boundaries inherit `border` `#EDE6DB`, which is **1.24:1** on the card and **1.16:1** on the background. In dark mode `#38383A` on `#1C1C1E` is **1.45:1**. shadcn derives `input` from `border`, so RSVP fields, the switch's off state and checkboxes would be hard to see. (DESIGN.md › Colors, "Unlisted shadcn tokens … derive from these"; SC 1.4.11). *Fix:* add an explicit `input` / `input-dark` token for form-control boundaries at ≥3:1 (e.g. `#8C8175`, 3.81:1 on white and 3.57:1 on the background; dark e.g. `#7A7A80`, 3.99:1 on the card). Keep `border` only for decorative card hairlines.
- **[high]** The focus indicator is not specified anywhere. `ring` "derives" from unnamed tokens, and on the tinted surfaces (primary-soft, decision-soft, blocked tint) and the dark card a default ring can fall below 3:1. For example, light primary on the dark card is 3.06:1, which is borderline. (DESIGN.md › Colors; EXPERIENCE.md › Accessibility Floor; SC 2.4.7, 2.4.11, 1.4.11). *Fix:* add `ring: {colors.primary}` / `ring-dark: {colors.primary-dark}` with a 2px ring and a 2px offset in the page background colour. State that it must be visible on every tinted row. Never use `outline: none` without this.
- **[high]** The undo toast is 5s and is the **only** undo path. `aria-live="polite"` is queued behind other speech and often isn't read before it expires. "Extended while focused" is useless because nothing moves focus to it, and keyboard users can't reach it in 5s. Undo is also offered for delegate, status change and mark done. (EXPERIENCE.md › Interaction Primitives, Accessibility Floor; SC 2.2.1, 4.1.3, 2.1.1). *Fix:* (a) set a toast minimum of 10s, pause on hover or focus, and make it persist while any toast is focused. (b) Add a documented shortcut to jump to the toast region (e.g. `F6` or `Alt+T`, as in sonner's `hotkey`). (c) **Add a timeless undo path**: each task created from ✓ gets *Undo* / *Remove* in Task detail history, and dismissed proposals appear under *Show dismissed (n)* in Needs you with *Restore*. Once undo is no longer time-bound, 2.2.1 no longer applies.
- **[high]** Focus is lost when a proposal row animates out after ✓ or ✕, and when a task leaves a list after status changes. Focus falls to `<body>`, so screen-reader and keyboard users lose their place. (EXPERIENCE.md › Component Patterns › Proposal row; Interaction Primitives; SC 2.4.3). *Fix:* after a row leaves, move focus to the next row's primary action, or to the previous one, or to the section header if the section is now empty. On Undo, restore the row and return focus to its ✓ button.
- **[high]** The ✓ confirm button is **30px**, which contradicts the spine's own 44×44 floor. The ✕ ghost button has no size, and both are icon-only with no specified accessible name. (DESIGN.md › components.confirm-button; EXPERIENCE.md › Interaction Primitives; SC 2.5.8, 4.1.2, 2.5.3). *Fix:* keep the 30px visual but give it a 44×44 hit area on phone (≥24×24 spacing on desktop). Specify `aria-label="Confirm: {title}"` / `"Dismiss: {title}"` (nb: "Bekreft: …" / "Avvis: …"). Apply the same rule to the menu button ("Menu" / "Meny"), the back control and the decision option pills.
- **[high]** Reflow is targeted at 375px and "200% zoom", but WCAG 1.4.10 requires **320 CSS px** (1280px at 400%) without 2D scroll. Norwegian's +30% string length plus one-row layouts (decision card title row plus Decide, option pills "on one row", proposal row action column, event card with count circle) will overflow at 320px. (DESIGN.md › Layout & Spacing; EXPERIENCE.md › Foundation, Accessibility Floor, Responsive; SC 1.4.10, 1.4.4). *Fix:* change the floor to "works at 320 CSS px and 400% zoom". Specify wrap behaviour: decision-card pills wrap and Decide drops below the title under ~360px; the proposal row's ✓/✕ stack under the text. Sticky bars (Send a request, Task detail action bar) must un-stick or collapse when the viewport height is below ~400px.
- **[high]** The Timeline's keyboard and screen-reader model is undefined. The spec only says "horizontal scroll with visible edge fade; tapping a task opens it". Swimlanes, dependency order and decision markers are purely spatial. (EXPERIENCE.md › Component Patterns › Timeline; SC 2.1.1, 1.3.1, 1.3.2, 2.4.3). *Fix:* make the scroll container `role="region"` with `aria-label="Timeline"` and `tabindex="0"` so arrow keys scroll it. Make each lane a labelled list (`<ul aria-label="Venue">`) in deadline or dependency order, with task items as links. Focusing an item scrolls it fully out of the edge fade (`scrollIntoView({inline:'nearest'})`). Each item's name includes date, status and "waits for X" or "decision point". Add a **List view** toggle (grouped by Role, linear), which also covers 1.4.10.
- **[high]** The forms and RSVP error pattern is not specified: no required or optional marking, no inline error, no error summary, and no focus handling between the one-question screens. The "Question 2 of 5" total is unstable because *No* ends the flow and plus-one is conditional. (EXPERIENCE.md › RSVP flow, Accessibility Floor, State Patterns › Save failed; SC 3.3.1, 3.3.2, 3.3.3, 1.3.1, 2.4.3). *Fix:* each question is a `<fieldset>` with its question as `<legend>` or `<h1>`. Focus moves to that heading on every step. Errors go inline via `aria-describedby`, with `aria-invalid`, and the message is re-announced. Show a visible *Back* control. The progress label counts only remaining applicable steps and updates when branching. Allergies use checkboxes plus an "Other" text field.
- **[medium]** The at-risk mustard outline `#C9A227` is **2.42:1** on white and **2.26:1** on `#FAF7F2`. Because "N at risk" text also carries the state this is not a strict 1.4.11 failure, but the mustard count circle and outline are the at-a-glance signal and are invisible to low-vision users. `at-risk-text` on the background is also only 4.74. (DESIGN.md › colors.at-risk, event-card-at-risk; SC 1.4.11). *Fix:* raise `at-risk` light to ≥3:1 on the background (e.g. `#A07F00`, 3.55:1 on the background and 3.8:1 on white), or make the outline decorative and state that the label is the sole required cue. The dark value `#E0B84A` is fine.
- **[medium]** The "measured" contrast paragraph is inaccurate. "Every status text colour ≥ 5.0 on its surface" is false: obsolete on the background is **4.75**, at-risk-text on the background is **4.74**, muted on the sidebar is **4.62**, primary on primary-soft (proposal title and active sidebar item) is **4.88**, muted on decision-soft (decision subhead) is **4.57**, and muted on primary-soft (proposal subhead) is **4.68**. All still pass, but builders will trust the claim and lighten them. (DESIGN.md › Colors › Contrast; SC 1.4.3). *Fix:* replace the claim with a pair table (text token × surface token → ratio) that includes the tinted surfaces. Mark the ≤4.7 pairs "do not lighten".
- **[medium]** The obsolete row relies on strikethrough and muted colour. Screen readers do not announce `line-through` (CSS) and mostly ignore `<s>`/`<del>`. The spine does not require the status word "Obsolete" on the row. (DESIGN.md › Task row › Obsolete; EXPERIENCE.md › State Patterns › Obsolete; SC 1.3.1, 1.4.1). *Fix:* the obsolete row shows the `minus-circle` icon plus the visible status word "Obsolete" / "Utgått", like every other state. Strikethrough is decorative. The row's accessible name includes "obsolete, option not chosen: {option}".
- **[medium]** Dynamic content is not announced. Results appearing after "Drafting tasks…", new proposals, rows collapsing out, "Show obsolete" and Guests tile filters change the page silently. Save-failed and role-revoked toasts are urgent but polite. (EXPERIENCE.md › State Patterns, Accessibility Floor; SC 4.1.3). *Fix:* use `role="status"` on the AI progress line and announce the outcome ("7 tasks proposed"). After a filter or toggle, announce the count ("Showing 16 pending guests"). Use `role="alert"` for *Couldn't save*, *Role revoked* and *Offline*. Keep `polite` for undo toasts. Never announce every realtime row insertion; debounce to "2 new items in Needs you".
- **[medium]** The sidebar active item is effectively colour-only. `primary-soft` on the `sidebar` background is **1.01:1** (the tint is invisible), and the blue text against normal foreground text differs by only **2.94:1**. (DESIGN.md › components.sidebar-item-active; SC 1.4.1, 1.4.11). *Fix:* add a non-colour cue (600 weight plus a 3px leading bar in primary, or a filled icon) and `aria-current="page"`.
- **[medium]** Decision page "options as selectable cards, one choice" has no semantics or selected-state spec. (EXPERIENCE.md › Decision page; SC 4.1.2, 1.4.11, 1.4.1). *Fix:* use a `radiogroup` of native radios styled as cards, with arrow-key navigation. The selected state gets a `circle-check` icon plus a ≥3:1 border (decision purple), not just a tint.
- **[medium]** The Guests summary "coming / declined / pending as a segmented bar" relies on colour segments. (DESIGN.md › Guest summary tiles; SC 1.4.1, 1.1.1). *Fix:* always print the numbers with words beside the bar ("60 coming · 4 declined · 16 pending"). The bar is `aria-hidden`. Tiles that filter the list are buttons with `aria-pressed`.
- **[medium]** There is no bypass mechanism. On desktop, 9+ sidebar links precede the content on every page. (EXPERIENCE.md › Navigation; SC 2.4.1). *Fix:* add a "Skip to content" / "Hopp til innhold" link as the first focusable element, with landmarks `nav` (labelled "Event") and `main`.
- **[medium]** SPA route changes: only Task detail and Decision move focus. Sidebar navigation, the wizard steps and Guest pages don't specify focus or `<title>`. (EXPERIENCE.md › Accessibility Floor; SC 2.4.2, 2.4.3, 4.1.3). *Fix:* every route sets `document.title` to "{Surface} – {Event} – Arrangly" and moves focus to the large-title `h1` (`tabindex="-1"`). Each wizard step does the same, with "Step 3 of 6".
- **[medium]** The top-right menu Sheet: the side it slides from, the trap and the ARIA are unspecified, and the button's DOM position relative to the title determines focus order. (DESIGN.md › Layout; EXPERIENCE.md › Navigation, Sidebar; SC 2.4.3, 4.1.2). *Fix:* the Sheet slides from the **right** (matching the trigger). The trigger has `aria-expanded`, `aria-controls` and the label "Menu" / "Meny". Focus is trapped while open, and the first item gets focus on open. Place the trigger after the `h1` in the DOM, or put it in a `header` landmark first, consistently on every page.
- **[medium]** Sticky and bottom bars (*Send a request*, the Task detail action bar) and bottom toasts can cover focused elements when tabbing. (EXPERIENCE.md › Responsive; SC 2.4.11). *Fix:* add `scroll-padding-bottom` equal to the bar height, and stack toasts above sticky bars, not over them.
- **[low]** Mixed-language content: document-level `lang` is covered, but user-written text (announcements, notes, requests, AI drafts) may be in the other language, and the language picker options should be in their own language. (EXPERIENCE.md › Foundation, Accessibility Floor; SC 3.1.1, 3.1.2). *Fix:* use `lang="nb"` (not `no`) and `lang="en"`. Picker options are "Norsk (bokmål)" `lang="nb"` / "English" `lang="en"`. Tag the ✦ Draft email with the language it was generated in. Accept that free text people write stays untagged, since that is an allowed limitation. Update `<html lang>` immediately on manual override.
- **[low]** Localised abbreviated dates ("lør. 24. okt.") read poorly in screen readers. (EXPERIENCE.md › Foundation; SC 1.3.1). *Fix:* wrap dates in `<time datetime>`. Give the deadline/metadata subheads an `aria-label` with the full form where abbreviations are used.
- **[low]** Section labels are "uppercase". If the strings are authored in caps, screen readers may spell them out. (DESIGN.md › Typography › Section label). *Fix:* author them in sentence case and use `text-transform: uppercase`. Make them `h2` with the count pill inside, e.g. "Needs you, 3".
- **[low]** Count circle and card borders: the neutral count-circle border `#EDE6DB` is 1.24:1, and the card hairline 1.16:1. This is acceptable only because they are decorative. The count circle still needs a name. (DESIGN.md › count-circle; SC 1.1.1). *Fix:* give it `aria-label="3 open tasks"`, and have the card link's name read "Lucas's 40th, Sat 24 Oct, Organizer, 3 open tasks, 1 overdue, 1 new task".
- **[low]** Push permission: asking on enable is correct, but the iOS "Add to Home Screen" requirement and the denial state are unspecified. (EXPERIENCE.md › Notification preferences, Responsive). *Fix:* if the browser permission is `denied`, show the switch off, with the text "Blocked in browser settings" plus how-to steps. Never re-prompt automatically. Explain the iOS step before the switch, in text rather than an icon.

## Verified OK

- Body text 15.32 (light) / 19.29 (dark); muted on card 5.34 / 5.93; primary on the background 5.21 / 8.00; white on primary 5.57; black on dark primary 8.00. The spine's claims match.
- Status text on white and on the dark card: done 5.39 / 8.42, waiting 6.04 / 8.28, overdue 6.25 / 6.03, decision 7.07 / 7.06, obsolete 5.07 / 5.22. Muted on the blocked tint is 4.54 (as claimed, at the floor).
- White on the light Decide button is 7.07. The overdue outline is 5.84 and the decision outline 6.61 on the background, so both pass 1.4.11.
- Status is paired with icon and word throughout. Blocked is never red. The event card outline is paired with "N overdue" / "N at risk".
- `prefers-reduced-motion` gives cross-fades only; no confetti; 150–250ms motion. No drag and drop (2.5.7) and no hover-only affordances.
- Push permission is requested only on user enable, and in-app notifications are always on.
- `Esc` closes the sheet and dialogs, and focus returns to the trigger. Full pages focus their title.
- Magic link expiry is explained with a recovery path rather than a generic error. Rem-based type respects browser text size.
- No fixed-width buttons, and labels wrap before truncating (good for Norwegian and 1.4.12).
