## Findings

Each finding: source, then disposition (fix now / defer / accept).

### F1. `main` CI has failed on every push, so `deploy` (`supabase db push`) has never run — fix now

- **Source:** `gh run list --branch main`: all six runs since 2026-10-14 `failure`, the `deploy` job `skipped` (`ci.yml:79-84`, `needs: checks`). Failing step is `.githooks/test.sh`: `FAIL: commit with trailer (want 0, got 2)` and `FAIL: main only in message text (want 0, got 2)` (run 39035746609, and the same two lines in runs 38648573884 and 38776221396). Branch and PR runs pass.
- **Cause:** the two failing checks run the Claude guard hook (`.githooks/test.sh:34-35`), which blocks commits on the checked-out branch, and CI checks out `main` on push. The self-test depends on which branch it runs on.
- **Consequence:** AGENTS.md says the cloud receives migrations only through CI from `main`. Two migrations (`20261014230000_abuse_limiter.sql`, `20261017120000_abuse_counters_bucket_shape.sql`) have therefore never reached the cloud project. Sign-up and every limiter call would fail there. A cleanup step also fails with `supabase: command not found` after the earlier failure, which hides the real error.
- **Disposition:** fix now (A1, A2). **Upstream lesson:** Story 1.3's acceptance ("quality gates run on every push") was proven on branches only; its done-check never ran against `main`.

### F2. Repeated form chrome and the password-rules list (duplication) — defer

- **Source:** `inputClass` is redefined in `app/signup/form.tsx:9`, `app/profile/forms.tsx:16`, `app/login/form.tsx:7`; the same classes are inlined in `app/forgot-password/form.tsx:52` and `app/reset-password/form.tsx:41`. The live rules list built from `passwordRules` exists in `app/signup/form.tsx`, `app/reset-password/form.tsx` and `app/profile/forms.tsx`.
- **Consequence:** the next stories that add forms (Epic 2 onward) will copy a fifth and sixth variant; a design-token change must be made in five places.
- **Disposition:** defer to before Epic 2's first form (A4). No duplicated logic rule was broken: schemas, `Result` and `refuse` are shared.

### F3. `src/modules/auth/actions.ts` grows to 341 lines with 15 exports — accept, watch

- **Source:** `git_evidence.py` net +378 across the epic; `grep` counts 15 exported or top-level async functions (sign-up, log-in, resend, forgot, reset, OAuth, six profile actions, log-out, `limit`).
- **Assessment:** one module owns auth (AD-2 wants the owning module to write its tables), the functions are short and uniform, so this is size, not a god class. It will cross a healthy size with the next auth story.
- **Disposition:** accept; split into `session`, `oauth` and `profile` files if any auth story adds more actions.

### F4. Deferred items accumulate in specs and the ledger; two ledger entries are stale — fix now (small)

- **Disposition:** close those entries (A3). **Lesson:** the ledger has no "resolved" convention, so stale entries read as open work.

### F5. Browser-level proof is missing for the toast and Sheet behaviours — defer (tracked in specs)
