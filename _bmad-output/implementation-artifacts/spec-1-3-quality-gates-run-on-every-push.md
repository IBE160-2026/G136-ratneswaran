## Intent

**Problem:** CI runs lint, format, Vitest, gitleaks and the hook test only. pgTAP, Playwright, type-check and the generated-types check are not gated, and nothing yet carries migrations to the cloud, so later stories cannot prove their RLS rules or their UI (issue #22, AD-15, AD-16).

**Approach:** Extend `.github/workflows/ci.yml` so every push starts local Supabase in Docker and runs `supabase test db`, Vitest and Playwright, plus `tsc --noEmit` and a regenerated-types diff. Add a deploy job for `main` that runs `supabase db push`, holding the three cloud secrets and inactive until the owner adds them.

## Boundaries & Constraints

**Always:** Branch and PR runs never see cloud credentials: the three secrets appear only in the deploy job's `env`, and that job runs only for a push to `main` after the checks job passes. The workflow keeps `permissions: contents: read`. `AI_LIVE` and `ANTHROPIC_API_KEY` are never set in CI, so AI code uses fixtures (AD-9). Local keys come from `supabase status -o env`, never hard-coded. pnpm only; third-party actions pinned to a major version as in the current file. `src/types/database.ts` is generated by `supabase gen types --local`, never hand-edited, and is excluded from Prettier and ESLint so the CI diff compares raw output. With the three secrets missing, the deploy job skips with a notice and does not fail `main`.

**Never:** Migrations, tables or policies (no schema exists yet; the types file is generated from the empty schema). Editing `_bmad/` or planning documents. Running `supabase db push`, `link` or any cloud command from a branch run or locally. `pnpm build` in CI (needs production env; stays deferred).

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Push to a branch | Any branch except `main` | `checks` runs all layers; no `deploy` job; no secret in scope | Any failing layer fails the run |
| Types drift | Committed `database.ts` differs from regenerated output | Step fails and prints the diff | Message says to run `supabase gen types` and commit |
| Merge to `main`, secrets set | Checks green | `deploy` runs `supabase link` then `supabase db push` | Failure fails the run |
| Merge to `main`, secrets missing | Checks green | `deploy` ends with a notice naming the missing secrets | Does not fail |
| Checks fail on `main` | Any layer red | `deploy` never starts (`needs: checks`) | N/A |
