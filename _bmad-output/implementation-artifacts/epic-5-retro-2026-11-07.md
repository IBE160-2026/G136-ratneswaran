## Findings

Dispositions: **fix** (action item), **defer**, **accept**.

### F-A: Architecture delta

- **A1 (low, accept).** No new cross-module imports. The only `tasks` → `events` imports are `eventPath` (`src/modules/tasks/actions.ts:7`) and `roleKeys` (`src/modules/tasks/timeline.ts:2`); nothing in events, guests or auth imports tasks.
- **A2 (medium, defer).** Two loader homes. The Timeline loader is in the module (`src/modules/tasks/timeline.ts`); the Dashboard and My tasks loader `loadListed` is in `app/events/[eventId]/tasks/load-listed.ts` (124 lines). The Dashboard's data layer therefore sits in `app/`. Each loader also rebuilds "what the viewer may read" on its own (`memberRoleIds` and `leadRoleIds` in `load-listed.ts:100-107`, `readable` in `timeline.ts:254`).

### F-D: Duplication

- **D1 (medium, fix).** The Dashboard classification exists three times: `classifyDashboard` (`src/modules/tasks/dashboard.ts`), `events_card_counts()` (`supabase/migrations/20261106120000_events_card_counts.sql`, whose comment says "Same scope and rules") and the card rules in `card-state.ts`. No parity test ties them. By reading, they match today. The 5.5 spec already records this residual risk.
- **D2 (medium, fix).** Overdue and blocked are derived twice: SQL `task_state` (zone-aware, `tasks_status.sql:158`) and `computeTimeline` (`timeline.ts:141`, from `dayNumber` and `dependsOn`). Blockers on the Timeline are limited to readable Roles (`timeline.ts:96-97`), so Dashboard and Timeline can disagree for a cross-Role dependency.
- **D3 (low, accept).** Without `?view` the page ships both swimlane and list in HTML and CSS picks one at 768px (`timeline-view.tsx:216,234-235`). Logic is shared (`useBarText`, `computeTimeline`); only markup doubles. 5.8 recorded this.

### F-G: Size growth

- No god-file. Current sizes: `timeline-view.tsx` 341 lines, `timeline.ts` 285, `load-listed.ts` 124, `timeline-list.tsx` 126, `on-track.tsx` 125, `dashboard.ts` 118.
- **G1 (low, accept).** `timeline.ts` mixes pure computation and I/O in one file; watch it when 4.8 adds Decision points.

### F-P: Pattern divergence

- Clean against AGENTS.md. Epic 5 added no Server Actions, so the Zod and Result rules did not apply. No `SECRET_KEY`, `console.log`, debugger or `.only` in added lines. Both migrations are new files and `database.ts` was regenerated (`38aea37`, `06d8843`). The one `console.error` (`timeline.ts:120`) logs ids only.

### F-S: Spec-to-implementation reconciliation and seams

- **S1 (medium, accept and record).** 5.9 is a Core-only deviation. Problem, "Decision card first", the awaiting-decision count, the open Decision Task and the Proposed card are not seeded or asserted (the schema has no Decision or Problem; Proposed needs AI). Only an absence guard exists (`e2e/flagship.spec.ts:45`, `/Needs your decision|Problem reported/`, strings that are not message keys). The deviation lives in the 5.9 spec's intent contract, not in `epics.md`. None of the deferrals reached `deferred-work.md`, which `git diff` shows unchanged in this range.
- **S2 (medium, fix).** 5.9 AC1 asks that pgTAP runs against the seed in CI. CI loads the seed once; re-seed idempotency is only proven in Playwright (5.9 deferred).
- **S3 (medium, fix).** Today pill clipped by the sticky Role column. It passed 5.7's review, was found by the owner-requested browser check after merge and fixed in `a214d9f`. The 5.7 Auto Run Result says "no visual check in a browser" and no test pins the pill's position. Upstream lesson: UI stories need a browser look before review, which the 5.8 runner did and the 5.7 runner did not.
- **S4 (low, accept).** Added beyond the ACs: the Role-holder landing is the Dashboard (5.2 Deviation) and `tasks.created_at` (`20261106130000`).
- **S5 (low, defer).** 5.4 delivered tests only: Show dismissed and Restore, the invitation slot and the role-revoked toast are not built; its last residual says the 3.9 toast AC needs the owner's decision.
- **S6 (low, verified).** 5.7 year-boundary weeks and both locales are pinned (`timeline-layout.test.ts:9,22`); region, `aria-label` and `tabIndex` are present (`timeline-scroller.tsx:60-62`). That focus scrolls a Task into view was checked only down to the `scroll-ml` classes.

### F-L: Lenses over the epic diff

- **L1 (pass, re-checked).** No other Role's Task title reaches a Role-holder in the Timeline HTML: unreadable lanes return `empty: true, tasks: []` (`timeline.ts:186`), `byId` and `waitsFor` see only readable Roles, and the list renders the same lanes.
- **L2 (medium, fix).** The no-leak assertion is narrower than the AC. `flagship.spec.ts:138` uses `getByText(title).toHaveCount(0)`, which does not see `aria-label` (the link name is `{title}, {dates}, …`), escaped text or the RSC payload.
- **L3 (medium, decide).** A viewer who owns a Task in a Role they do not hold: RLS allows the read (`20261103120000_tasks.sql:44`, `holds_role(role_id) or owner_user_id = auth.uid()`), the Dashboard lists it (`load-listed.ts:100-107`), but the Timeline drops it because that lane is not `readable`. The flagship seed avoids the case. Either is defensible; it must be a decision, not an accident.
- **L4 (low, accept).** AD-13 holds: Timeline order is computed per request, no stored order column (`tasks_created_at.test.sql` asserts it).
- **L5 (low, fix).** About 155 `current_date` uses remain in e2e and pgTAP fixtures. They fail between 00:00 and 01:00 Oslo time (UTC date vs Event-zone date). Reproduced locally on 2026-11-07 at 00:06 (`Overdue 6 days` against an expected 5).
- **L6 (low, defer).** `loadTimelineInput` has no bound on Task count; the 300-Task check is an Epic 11 carry-forward.
